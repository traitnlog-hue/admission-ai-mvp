# GACHI 공식 입시 데이터 운영 기준

## 1. 판단 기준

입시 추천과 컨설팅에 노출하는 수치는 **대학 공식 모집요강 또는 정부·대교협 공식 출처**만 사용한다. 블로그, 커뮤니티, 생성형 AI 응답은 탐색 보조 자료일 뿐 전형 수치의 출처가 될 수 없다.

| 데이터 영역 | 기준 출처 | 반영 방식 |
| --- | --- | --- |
| 대입 제도·2028 변경 | 교육부 공지 | 정책 변경 검토 후 규칙 DB 갱신 |
| 대학·학과 메타데이터 | 공공데이터포털·대교협 OpenAPI | 서버 일 1회 동기화, 원본 응답·갱신 시각 기록 |
| 전형·모집인원·일정·수능최저 | 각 대학 입학처 모집요강 | PDF 원문 등록 → 구조화 추출 → 관리자 2인 검수 → `verified` 공개 |
| 전년도 입시 결과 | 대학 입학처/대입정보포털 공시 | 해당 전형 연도·산출 기준을 분리해 저장 |

## 2. 현재 등록된 기준 출처

`backend/data/official_sources.json`에 교육부, 대입정보포털 어디가, 공공데이터포털·대교협, 서울대학교, 고려대학교, 연세대학교의 출처 레지스트리를 저장한다. 앱과 API는 `GET /api/official-data/sources`로 출처·검수 상태·최근 반영 이력을 확인할 수 있다.

첨부된 서울대학교 2027학년도 안내는 수시·정시 전형, 모집인원, 일정, 수능 응시영역과 교과이수기준을 포함하므로 서울대 전형 데이터의 1차 원문으로 등록한다. 고려대·연세대 PDF는 `review_required` 상태로 등록하며, 수치 추출 뒤 관리자가 전형별로 확인하기 전에는 추천 엔진의 `verified` 데이터로 사용하지 않는다.

## 3. 관리자 검수 흐름

1. 대학 입학처에서 해당 연도 모집요강과 정정 공지를 확인한다.
2. 원문 URL, 발행일, 확인일, 파일 SHA-256을 원문 저장소에 기록한다.
3. 모집단위 × 전형 단위로 CSV를 작성한다. 반드시 `source_url`, `source_title`, `verified_at`을 채운다.
4. 담당자 2인이 모집인원·전형방법·수능최저·면접/논술 여부를 대조한다.
5. `POST /api/admin/official-sources/{source_id}/import-admissions`에 검수 CSV를 등록한다.
6. 서비스 화면에는 출처·확인일·`verified` 상태를 항상 함께 노출한다.

이 API는 `ADMIN_API_TOKEN`이 설정된 서버에서만 허용된다. 원문을 자동 OCR한 결과나 사람이 검수하지 않은 CSV는 절대 서비스에 바로 반영하지 않는다.

## 4. Google Cloud 권장 구조

```text
공식 원문(PDF/API)
  → Cloud Storage (원문·해시·보존 정책)
  → Cloud Run 수집/정규화 작업
  → 검수 대기 테이블 (Cloud SQL PostgreSQL)
  → 관리자 승인
  → verified 입시 DB / 앱 API
```

- API 키와 공공데이터포털 서비스키는 Secret Manager에만 저장한다.
- Cloud Scheduler는 **허용된 API 출처만** 호출한다. 대학 모집요강 PDF는 정정 여부 판단이 필요하므로 자동 공개하지 않는다.
- Cloud Storage에는 원문을 최소 기간 보관하고, 학생부·성적표 같은 학생 개인정보는 이 파이프라인에 넣지 않는다.
- Cloud Run은 서비스 계정(최소 권한), Cloud SQL은 백업과 감사 로그, 예산 알림은 별도로 설정한다.
- 예산 알림은 청구를 자동 차단하지 않으므로 Cloud Run 최대 인스턴스·Scheduler 호출 횟수·애플리케이션 일일 한도를 함께 설정한다.

## 5. 운영 금지 항목

- 대학 공식 PDF를 근거 없이 AI가 요약한 수치만으로 `verified` 처리
- 입시 연도·전형명·모집단위·정정 공지 버전을 섞어 노출
- 학생부 원본·성적표 원본을 공개 데이터 수집 버킷에 저장
- 출처와 확인일 없이 합격선·경쟁률·모집인원을 사용자에게 제시
